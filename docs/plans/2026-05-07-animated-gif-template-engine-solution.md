# Animated GIF Template Engine Solution

Decision: build an animated template engine, not a prompt-only GIF generator.

The video model should never be responsible for recreating the full template. It should only generate masked visual regions that are safe to vary. Layout, text, colors, chart paths, badges, UI chrome, product slots, timing, crops, and final GIF/WebP export should be deterministic.

## Why

The first Sora 2 test showed the generic failure mode:

- It treated the reference as inspiration, not a strict source of truth.
- It changed chart geometry, added extra points, duplicated `WITH TENOR`, and introduced a gold glow.
- It drifted from the intended Tenor red/orange.
- It changed axis label size/orientation.
- It inserted Tenor product where the source template had no competitor product slot.

Those are not one-off prompt issues. They are renderer ownership issues. Anything that must match the template should be owned by code.

## Core Principle

Every source GIF becomes a structured `template_manifest`.

The manifest decides:

- What is locked and must be redrawn or preserved exactly.
- What can be brand-swapped.
- What can be product-swapped.
- What can be copy-swapped.
- What can be regenerated by AI.
- What should be omitted.

The final output is assembled from the manifest, not trusted to emerge from one model prompt.

## Pipeline

1. Ingest source GIF.
   - Download bytes.
   - Compute hash.
   - Extract dimensions, duration, frame count, frame delays, and representative frames.
   - Create first/mid/last frame sheets for review.

2. Analyze template structure.
   - OCR visible text.
   - Detect logos, brand text, product/package slots, badges, UI chrome, people, background regions, chart/shape paths, counters, and repeated layout zones.
   - Track motion across frames with bounding boxes, masks, paths, and timing.
   - Classify every detected element into a layer policy.

3. Build `template_manifest`.
   - Store canvas, crop, rounded-corner mask, source timing, layers, editable slots, color roles, text roles, masks, and motion curves.
   - Record evidence for every product/brand replacement decision.

4. Human review checkpoint.
   - Show source keyframes with detected layer boxes/masks.
   - Show the manifest summary.
   - Require approval before paid model calls.
   - If product-slot detection is uncertain, fail with a clear review-required error.

5. Render deterministic base.
   - Draw locked vector/text/UI/chart/badge layers from code.
   - Apply exact brand colors from the approved brand/design system.
   - Preserve source layer dimensions, font scale, rotations, alignment, and positions.
   - Use source timing and easing unless explicitly overridden.

6. Generate only approved model regions.
   - If the template has a lifestyle/photo/UGC region that needs new pixels, generate that masked region only.
   - Do not ask the model to render locked text, charts, badges, product slots, axes, labels, or logos.
   - Do not attach product references unless the manifest says a product replacement slot exists.

7. Composite final frames.
   - Place generated regions behind deterministic overlays.
   - Apply masks and z-order from the manifest.
   - Export MP4, GIF, and animated WebP with deterministic ffmpeg settings.

8. QA and compare.
   - Produce side-by-side source vs output contact sheets.
   - Score template fidelity, motion fidelity, copy/compliance, product-slot correctness, and production usability.
   - Record model, prompt hash, source hash, manifest hash, cost, and output paths.

## Layer Policies

| Policy | Meaning | Render owner |
| --- | --- | --- |
| `locked_source_region` | Preserve/source-match the visual area with no semantic edits. | Deterministic renderer |
| `deterministic_rebuild` | Rebuild from geometry/text/path data. | Deterministic renderer |
| `brand_swap` | Replace source brand text/logo with target brand. | Deterministic renderer |
| `product_swap` | Replace competitor product with target product. | Deterministic renderer |
| `copy_swap` | Replace text with approved final copy. | Deterministic renderer |
| `generative_region` | Generate new pixels inside a mask. | AI model, then deterministic composite |
| `omit` | Remove the source element. | Deterministic renderer |

The default policy is `deterministic_rebuild` or `locked_source_region`, not `generative_region`.

## Product Insertion Rule

Product insertion is conditional, not automatic.

The renderer may insert a product only when the manifest has:

```json
{
  "productReplacement": {
    "hasCompetitorProductSlot": true,
    "replacementRequired": true,
    "slotEvidence": [
      "visible packaged product",
      "competitor product logo",
      "bottle/pouch/tub/box silhouette"
    ],
    "slotBox": [0, 0, 0, 0],
    "slotMask": "..."
  }
}
```

If `hasCompetitorProductSlot` is `false`, product references are not attached to the model and no product is inserted into the final render.

This fixes the item `05` issue: the source chart GIF has no competitor product slot, so Tenor Daily Drive Essentials should not appear.

## Color Rule

Brand colors are deterministic.

The manifest stores semantic color roles:

```json
{
  "colorRoles": {
    "brandAccent": "#C83232",
    "axisText": "#C83232",
    "primaryLine": "#C83232",
    "comparisonLine": "#FFFFFF",
    "background": "#050505"
  }
}
```

The renderer applies these exact values. The model is never asked to approximate brand red, line color, text color, glow, or axis color.

## Text Rule

Text is deterministic unless explicitly approved otherwise.

For every text layer:

```json
{
  "id": "y_axis_label",
  "type": "text",
  "policy": "brand_swap",
  "text": "ENERGY LEVEL",
  "box": [52, 236, 30, 360],
  "rotationDegrees": -90,
  "fontFamily": "source_match_or_brand_font",
  "fontSize": 40,
  "letterSpacing": 18,
  "colorRole": "axisText",
  "textTransform": "uppercase"
}
```

The model does not render this text. That prevents smaller labels, flipped labels, duplicate phrases, and warped text.

## Motion Rule

Motion is deterministic whenever it belongs to a template layer.

Examples:

- Chart line draw-on paths.
- Counter number increments.
- Badge fade/slide/scale.
- UI screenshot scrolls.
- Before/after panel swaps.
- Product reveal.
- Caption reveal.
- Collage tile motion.

The manifest stores per-layer timing:

```json
{
  "timing": {
    "startSeconds": 0.4,
    "endSeconds": 2.4,
    "easing": "source_sampled",
    "sourceFrameKeys": [0, 4, 9, 15]
  }
}
```

If timing cannot be extracted with enough confidence, the system stops for manifest review instead of guessing.

## Template Types

This is not chart-specific. The same model works for different GIF families:

| Template family | Locked deterministic layers | Possible AI-generated region |
| --- | --- | --- |
| Chart/graph/counter | Axes, labels, lines, numbers, background crop, timing | Optional background texture only |
| Product/badge graphic | Product slot, badge icons/text, claims, layout, shadows | Background/lighting texture |
| Social screenshot/UI | App chrome, username zones, caption rows, buttons, comments | Post image/video region |
| Before/after | Panel geometry, labels, divider, timing | Human/photo panels if new people are required |
| Customer collage | Grid geometry, rating badge, count text, tile masks | Individual customer/photo tiles |
| UGC/lifestyle | Captions, product slot, UI/text overlays, crop | Human/background motion |
| Logo/title card | Typography, logo, mask, transition timing | Background texture or particles |

## Model Comparison Changes

The model comparison should score two things separately:

- `generativeRegionQuality`: how good the AI region is inside its mask.
- `finalCompositeFidelity`: how close the deterministic final GIF is to the source template.

For chart/text-heavy templates, model score may be `not_applicable` because no model call should be needed.

## Failure Conditions

The system should error cleanly when:

- OCR cannot confidently identify source text that must be preserved or swapped.
- Product-slot detection is uncertain.
- A layer is important but cannot be tracked across frames.
- Brand color or final copy is missing for a required replacement.
- The requested model cannot accept the required masked input or duration.
- The generated region crosses outside its allowed mask.

No silent fallback, no automatic model switching, and no product insertion unless the manifest authorizes it.
